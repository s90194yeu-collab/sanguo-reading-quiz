# 內容包格式（每回一份 JSON）

一回的全部內容（原文、題庫、戰況、註釋、人物……）寫在**一個 JSON 檔**裡，用試算表選單「三國演義閱讀檢測 → 匯入內容包」貼上，系統先檢查、沒有錯誤才寫入，寫入後該回為「待審」，教師在後台「內容審核」預覽後上架。

- 完整範例：`packs/第一回.json`（第一回現行內容，檢查通過）
- 原文骨架：`python3 tools/epub_extract.py 三國演義.epub 6 > packs/第六回.json`
- 離線檢查：`node tools/check_pack.js packs/第六回.json`（規則與匯入時完全相同）

所有欄位名稱都是中文；**字串一律用繁體（教育部標準字體）**。沒有的區塊可以省略或給空陣列。

## 頂層欄位

| 欄位 | 型別 | 必填 | 說明 |
|---|---|---|---|
| 格式版本 | 數字 | 是 | 目前為 `1` |
| 回 | 整數 | 是 | 1～120 |
| 回次 | 字串 | 是 | `第六回`、`第一百二十回` |
| 回目 | 字串 | 是 | 上下聯以「｜」分隔：`焚金闕董卓行兇｜匿玉璽孫堅背約` |
| 校勘 | 字串陣列 | 否 | 對 epub 改字的紀錄，例：`"洛陽北都尉→洛陽北部尉"`（epub_extract 會自動產生） |
| 原文 | 字串陣列 | 是 | 一段一個字串；詩詞段落前加 `〔詩〕`。**必須逐字取自 epub_extract 的輸出，不可改寫、刪減、補字** |
| 題庫 | 陣列 | 是 | 見下 |
| 戰況 | 陣列 | 建議 | 見下；沒有戰事的回也要有「平時」幕 |
| 註釋 | 陣列 | 建議 | `{ 詞語, 注音, 解釋 }`；詞語必須出現在原文 |
| 專名 | 陣列 | 建議 | `{ 詞, 類別, 說明 }`；類別：人名／地名／朝代／年號／書名／官名 |
| 人物 | 陣列 | 新人物才填 | `{ 姓名, 別稱:[…], 陣營, 首次出場回, 簡介 }`；簡介**不可劇透**（不要寫「後來」「最終」） |
| 人物事蹟 | 陣列 | 建議 | `{ 姓名, 事蹟 }`：本回這個人做了什麼（只寫本回） |
| 人物關係 | 陣列 | 否 | `{ 人物甲, 人物乙, 關係, 從第幾回起 }` |
| 地點事件 | 陣列 | 建議 | `{ 年代, 地點, 事件, 經度, 緯度, 勢力 }`；勢力供「勢力版圖」著色 |
| 人物造型 | 陣列 | 新人物才填 | 見下 |
| 勢力 | 陣列 | 否 | 新勢力才填：`{ 勢力, 主色, 副色, 關鍵字:[…], 說明 }` |
| 插圖 | 陣列 | 否 | `{ 標題, 插在第幾段之後, 圖說, 生圖提示詞 }`；圖檔由教師另外補 |
| 回末小結 | 物件 | 建議 | `{ 本回大事:[一行一件], 名句, 想一想 }` |

## 題庫（建議 20 題，系統每次抽 10 題）

```json
{ "題號": 1, "類型": "劇情", "題幹": "……", "選項": ["甲", "乙", "丙", "丁"], "答案": "B", "解析": "……", "對應段落": 6, "人物": "張角" }
```

- 類型：劇情／文意理解／人物／意象／概念／修辭（系統依類型分層抽題，各類型都要有）
- 選項 4 個、互不重複；答案 A～D，**整份題庫的答案分布要平均**（前端會再洗牌，但仍請平均）
- 對應段落：答案依據所在的段（1 起算），作答後學生可按「看原文第 N 段」
- 解析：說明為何正確，並指出其他選項錯在哪
- 人物（選填）：作答後顯示該人物小卡

## 戰況（每一列＝一幕畫面）

```json
{
  "段": 10, "錨句": "遣副將鄧茂出戰", "場景": "單挑", "標題": "張飛對鄧茂",
  "背景": "戰場", "騎馬": "雙方", "頭像": "張飛",
  "甲方": { "名稱": "張飛", "人物": ["張飛"], "兵力": "", "勢": "相持", "勢力": "劉備" },
  "乙方": { "名稱": "鄧茂", "人物": ["鄧茂"], "兵力": "", "勢": "相持" },
  "說明": "程遠志遣副將鄧茂出戰，張飛挺丈八蛇矛出陣迎戰。",
  "依據段": 10,
  "預測": { "問題": "……你認為接下來會怎麼發展？", "選項": ["……", "……", "……"] }
}
```

**畫面何時出現**：學生讀到第「段」段的「錨句」時換成這一幕，一直維持到下一幕。錨句空白＝段首。錨句必須**逐字**出現在該段（標點也要一樣），否則匯入會被擋下。

| 欄位 | 規則 |
|---|---|
| 場景 | 軍陣（兩軍對陣，會畫兵陣）／單挑（一對一）／謀略（計策、伏兵）／平時（沒有戰事，只畫登場人物） |
| 背景 | 戰場、黃昏、夜、桃園、水戰、攻城、火攻、宮廷、營帳；空白＝依場景（軍陣→黃昏、單挑→戰場、謀略→夜、平時→桃園） |
| 騎馬 | 甲／乙／雙方；原文有「拍馬」「縱馬」「落馬」等才填 |
| 頭像 | 說明列左側的人物頭像；空白＝甲方第一人 |
| 甲方／乙方.人物 | 最多 4 人，會依序排成列；名字要和「人物造型」對得上，否則套用勢力色的一般兵造型 |
| 兵力 | **原文有寫的數字才填**，而且要逐字出現在原文（如「五萬」「四五十萬」）；原文沒寫就留空 |
| 勢 | 佔優／相持／潰敗；平時幕不填。這是**依文意示意**，不是數值 |
| 勢力 | 空白＝依「勢力」表的關鍵字判斷；需要指定時才填（例：第一回的董卓仍屬「漢廷」） |
| 依據段 | 「看原文第 N 段」與「找依據」的目標段；空白＝同「段」 |
| 預測 | 不計分的小問題，學生讀到這幕時詢問、讀到**下一幕**時提示「對照原文看看」。所以預測要放在**結果揭曉的前一幕**，選項 2～4 個，其中一個符合後文、其他合理但不符 |

撰寫原則（教學上的底線）：

1. 戰況完全跟著原文走，不可加入原文沒有的勝負、人物或兵力。
2. 同一場戰事的轉折（相持→佔優／潰敗）要各自成一幕，錨句放在轉折句上，這樣「找依據」才有意義。
3. 說明用一兩句白話概括該幕原文，不超過 50 字（面板只顯示兩行）。
4. 一回約 15～30 幕；每 1～2 段至少一幕，學生捲動時才看得到變化。

## 人物造型（16-bit 像素人物）

```json
{ "人物": "呂布", "比對": "姓名", "頭飾": "冠", "鬍鬚": "無", "武器": "戟", "髮色": "#1b1b22", "纓色": "#d8412f", "甲色": "#6a58a8", "衣色": "#44366e", "膚色": "#f0c29a", "鬍色": "#1b1620", "坐騎色": "#c0392b" }
```

- 比對：姓名（完全相同）／關鍵字（軍名或人名含此字，用於「黃巾」「官軍」這類一般兵）
- 頭飾：盔／頭巾／冠／亂髮／幘／兜帽／光頭
- 鬍鬚：無／長鬚／虯髯／八字／山羊
- 武器：劍／雙劍／矛／偃月刀／戟／羽扇／弓／無
- 顏色一律 `#RRGGBB`；依原文外貌描寫（例：關羽「面如重棗」→ 膚色偏紅；赤兔馬 → 坐騎色紅）
- 已建立的人物（見試算表「人物造型」）不必重填；要改造型才填

## 勢力（固定配色，120 回一致）

已建立：漢廷（赤）、黃巾（黃）、劉備（綠，日後的蜀）、曹操（藍，日後的魏）、孫堅（橙，日後的吳）、董卓（紫）、群雄（灰褐）。新勢力（如袁紹、呂布、袁術）第一次出現時在內容包「勢力」加一筆；關鍵字填軍名或人名，系統用它自動判斷每一方屬於哪個勢力。

## 檢查規則摘要（匯入時自動執行）

錯誤（會擋下匯入）：回／回次／回目格式、原文空段或疑似簡體字、題目缺欄或答案不在 A～D、對應段落超出範圍、錨句不在該段、場景／背景／勢／騎馬的值不合法、兵力數字不在原文、註釋詞語不在原文、經緯度不在中國範圍、造型或顏色值不合法。

提醒（不擋）：題數不是 20、答案分布偏斜、戰況順序顛倒、軍陣沒填勢、人物不在人物表、人物簡介可能劇透、最後一幕放預測、專名不在原文。
