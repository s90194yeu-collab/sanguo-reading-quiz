# 交接文件：《三國演義》閱讀檢測網站（給 Gemini）

> 專案：https://github.com/s90194yeu-collab/sanguo-reading-quiz
> 委託人：闕宏宇老師（南山中學國文科）。回覆一律用**繁體中文**，交付**完整可直接使用**的成品，不要草稿或片段。

## 1. 這個網站是什麼

高中生逐回閱讀《三國演義》的網站（Google Apps Script 網頁應用程式＋Google 試算表）。每回有原文、註釋、專名號、人物小卡，以及：

- **閱讀檢測**：每回題庫 20 題，每次分層抽 10 題、選項洗牌、伺服器端批改。
- **16-bit 戰況畫面**：跟著學生**讀到的原文位置**顯示雙方形勢（佔優／相持／潰敗），與作答完全無關，避免學生以為操作能改寫史實。
- **找依據、預測、圖鑑、戰報卡、勢力版圖**：都建立在「戰況」資料上。

第一回已全部完成，是所有後續回目的**標準範本**：`packs/第一回.json`。

## 2. 你的任務

依序為**第二回起**每一回產生一份「內容包」（JSON），交給老師匯入、審核、上架。

- 第 2～5 回：原文、註釋、專名、人物、地點已在網站上，但題庫只有 5 題、沒有戰況。請補成完整內容包（20 題＋戰況＋預測＋造型），原文沿用不改。
- 第 6 回起：全部從頭產生。
- 一次做一回，交給老師確認後再做下一回。

## 3. 不可違反的原則

1. **原文以好讀版 epub 為唯一底本**（毛宗崗評本系統）。一律由 `tools/epub_extract.py` 產生，**逐字照錄**，不可改寫、刪減、補字、改標點。發現疑似訛字時不要直接改，列在回覆中請老師決定；老師同意後才加進 `epub_extract.py` 的 `FIX` 校勘表。
2. **戰況只依原文**：不可出現原文沒有的勝負、人物、兵力。兵力數字必須逐字出自原文；原文沒寫就留空。「勢」只是依文意示意。
3. **不劇透**：人物簡介、事蹟、題目、預測選項都只能用到本回為止的內容。
4. **字形**：繁體、教育部標準字體（「青」不是「靑」、「即」不是「卽」）。直排文字由右至左。
5. **教師把關**：匯入後是「待審」，學生看不到；由老師預覽後上架。你的工作是讓老師審得輕鬆，不是替老師決定。

## 4. 每一回的工作流程

```bash
# 1) 取原文骨架（需要老師給的 epub 檔；pip install opencc-python-reimplemented）
python3 tools/epub_extract.py 三國演義.epub 6 > packs/第六回.json

# 2) 依 docs/內容包格式.md 填入題庫、戰況、註釋、專名、人物、事蹟、關係、地點、造型、勢力、插圖、回末小結

# 3) 檢查（規則與網站匯入時完全相同；有 ✕ 錯誤就修到沒有）
cd tests && npm install && cd ..
node tools/check_pack.js packs/第六回.json

# 4) 確認原文仍與 epub 一致
python3 tools/epub_extract.py 三國演義.epub 6 --compare packs/第六回.json
```

5) 交付：JSON 檔，加上一份**審稿表**（Markdown），讓老師快速核對：
   - 題庫：題號、類型、題幹、正解、依據段（一題一列）
   - 戰況：幕次、段、錨句、場景、甲方（勢）、乙方（勢）、兵力、說明（一幕一列）
   - 新人物與造型、新勢力
   - 疑似訛字或需要老師判斷的地方
6) 老師在試算表選單「三國演義閱讀檢測 → 匯入內容包」貼上 → 檢查 → 匯入 → 教師後台「內容審核」預覽 → 上架。

## 5. 內容撰寫規範

完整欄位與規則見 **`docs/內容包格式.md`**，範例見 **`packs/第一回.json`**。重點：

### 題庫（20 題）
- 類型比例參考第一回：文意理解 8、人物 8、概念 4（也可用劇情、意象、修辭）。每種類型至少 3 題，系統才能分層抽題。
- 題目要能在原文找到依據，「對應段落」填依據所在段；不要考需要課外知識才能答的題目。
- 誘答選項要合理：常見誤讀、相近情節、張冠李戴，不要放明顯荒謬的選項。
- 解析說明為何正確，也點出主要誘答錯在哪；可引原文短句（加引號）。
- 答案 A～D 平均分配（每個字母 4～6 題）。
- 文意理解題可考文言詞義、句意、言外之意；人物題考性格、動機、關係；概念題考章回小說的手法（伏筆、映襯、回末懸念、詩詞評贊等）。

### 戰況（約 15～30 幕）
- 從回首到回末連續覆蓋，沒有戰事的段落用「平時」幕，列出登場人物。
- 戰事的每個轉折各成一幕：錨句放在轉折句（如「手起處」「一齊縱火」），這樣學生「找依據」時點的就是那句話。
- 錨句取該段中**短而獨特**的片段（4～10 字），逐字複製。
- 單挑：雙方各一人；原文寫「拍馬」「縱馬」「落馬」時填「騎馬」。
- 背景依原文情境挑：火攻、水戰、攻城、宮廷、營帳……
- 預測：每回 2～4 題，放在**結果揭曉的前一幕**，問「你認為接下來……」，三個選項中一個符合後文。不計分，目的是讓學生先想再讀。
- 頭像：說明列的主角，通常是該幕開口或行動的人。

### 註釋、專名
- 註釋挑高中生不易懂的文言詞、典故、官職、器物；解釋簡短，必要時加注音。第一回 51 條可作分量參考。
- 專名：本回出現的人名（含字號）、地名、朝代、年號、書名、官名。已在前面回目登錄、且類別相同的詞可不重複（回＝0 的通用專名除外）。

### 人物、造型、勢力
- 新登場的重要人物才建「人物」；簡介只寫身分與本回以前已知的事，不劇透。
- 造型依原文外貌描寫（例：呂布「頭戴三叉束髮紫金冠，體掛西川紅錦百花袍」→ 冠、紫／紅配色；赤兔馬 → 坐騎色紅）。查不到描寫就依身分選合理造型。
- 勢力固定配色：魏藍、蜀（劉備）綠、吳（孫氏）橙、漢廷赤、黃巾黃、董卓紫、群雄灰褐。新勢力（袁紹、袁術、呂布、劉表……）第一次出現時新增一筆，顏色避開既有勢力。

### 地點事件、回末小結、插圖
- 地點附經緯度（今地，約略即可），「勢力」填當時控制者，地圖會著色。
- 回末小結：本回大事 4～6 件（一行一件）、一句名句（原文逐字）、一個開放的「想一想」。
- 插圖：每回 **5 張**（依情節關鍵轉折按時間順序排列），寫「圖說」「生圖提示詞」（古典連環畫風格、人物、時代服飾、構圖，頂部留白、不要文字與自帶氣泡）與「對話氣泡」（`類型|說話者|x|y|w|tx|ty|台詞`）；圖檔由老師另外生成上傳。

## 6. 若需要修改程式

一般情況**只需要產生內容包，不必改程式**。真的要改時：

| 位置 | 內容 |
|---|---|
| `Code.gs` | 工作表名稱與欄位（`SHEET`、`HEAD`）、設定預設值、選單、初始化 |
| `Student.gs` | 學生端 API：目錄、`chapterFull_`（讀試算表組成一回）、存檔 |
| `Quiz.gs` | 抽題、洗牌、批改 |
| `Content.gs` | 內容包檢查 `validatePack_`、匯入 `importPack`、匯出 `exportPack_`、審核、造型與勢力、圖鑑、遊戲進度 |
| `Teacher.gs` | 教師後台 |
| `Index.html` | 網頁骨架；`<?!= include('檔名') ?>` 併入 `css` 與各 `js_*` |
| `js_px.html` | 16-bit 像素引擎：人物點陣、馬、頭像、九種場景 |
| `js_battle.html` | 戰況面板、閱讀位置、找依據、預測、版面 |
| `js_codex.html` | 圖鑑、戰報卡 |
| 其他 `js_*.html` | 核心工具與登入、閱讀頁、地圖、作答、展示模式、教師後台 |

規則：
- `js_*.html` 是**純 JavaScript**（沒有 `<script>` 標籤），全部併入同一個 `<script>`，彼此共用全域函式。
- 新增工作表欄位一律**加在最後一欄**，`setupSheets` 會自動補標題，舊資料不受影響。
- 改完一定要跑測試：`cd tests && npm install && npm test`（伺服器端用 `gasmock.js` 在 node 模擬 Apps Script，瀏覽器端用 Playwright）。全部通過才交付。
- 不要引入框架或建置工具；不要把 epub 放進 repo。

## 7. 部署（由老師在 Apps Script 編輯器操作）

### 7.1 一般流程

1. 把 repo 中有改動的 `.gs` 與 `.html` 貼到 Apps Script 專案（新增檔案的做法見 7.2）。目前共 6 個 `.gs`、13 個 `.html`（另有內嵌插圖檔 `img_*`，沒改就不用動）。
2. 執行 `setupSheets`（補新工作表與新欄位）；第一次升級到這個版本時再執行 `applyChapter1Upgrade`。
   - `setupSheets` 在 `Code.gs`、`applyChapter1Upgrade` 在 `Content.gs`。編輯器上方的函式下拉選單只列出「目前開啟那個檔案」裡的函式，要先點開該檔再選。
   - 第一次執行會跳出「需要授權」，必須由老師本人按「審查權限」並允許。
3. 「部署 → 管理部署作業 → 編輯（鉛筆）→ 版本：建立新版本 → 填版本說明 → 部署」，網址不變。
4. 試算表選單「清除網站快取」。
5. 驗證：用無痕視窗開網址，加 `?v=版本號` 避免看到舊快取，從訪客試讀第一回確認戰況面板、「版面▾」、目錄頁「圖鑑」都在。

### 7.2 新增檔案的做法（容易出錯）

- 檔案清單上方的「＋」→ 選「指令碼」（`.gs`）或「HTML」，等約 3 秒，檔名欄會出現；輸入檔名**不含副檔名**，按 Enter。
- 如果選單點了沒反應，或畫面上殘留名為「未命名.gs」的空檔，把它刪掉（檔案旁選單 → 刪除），不要留著。
- 檔名必須與 repo 完全相同。`Index.html` 用 `<?!= include('css') ?>` 這類寫法，按檔名併入其他檔，名字錯了整個網站會空白。
- 專案裡第一個檔案名稱可能是中文的「程式碼.gs」，內容放 `Code.gs` 即可。所有 `.gs` 共用同一個全域範圍，檔名不影響執行。
- 貼完後重新整理編輯器頁面，確認每個檔案的內容都還在，再繼續。

2026-11-13 已部署第 11 版，內容對應 GitHub 提交 55a46e6。之後每次改程式，請在版本說明寫上對應的提交編號。

## 8. 已知問題與待辦

- 第 2～5 回需補成 20 題＋戰況（見第 2 節）。
- 試算表「設定」的「副標題」請老師確認；題庫第一回第 13、15、16 題偏詮釋，可再請老師審。
- 像素字型（俐方體11號）由 jsDelivr 載入；學校網路擋外部 CDN 時會退回楷體，不影響功能。
- 戰況的 `k`（幕的序號）依試算表列順序；學生的「找依據」「預測」紀錄以此對應。**已上架的回目若要調整戰況，盡量只改內容、不要插入或刪除列**，否則學生紀錄會對錯幕。
- 戰況面板的預測、找依據都不計分，也不進成績表；之後若要在後台統計，可從「存檔」草稿的 `g` 欄位讀取。
